# 设备投屏

设备投屏模块在应用内实时镜像已连接 Android 设备的屏幕，并允许使用鼠标和键盘反向控制设备。适用于检查界面行为、在性能分析旁复现交互、或在真机上验证帧问题。

## 开始投屏

1. 用 USB 连接已开启 USB 调试并授权本机的设备。
2. 从首页卡片或导航栏打开**设备投屏**。
3. 在下拉框中选择设备（点击**刷新**重新扫描），点击**开始投屏**。

应用会向设备 `/data/local/tmp` 推送一个约 100 KB 的 scrcpy server，建立 adb 反向隧道后开始镜像。设备上不安装任何应用，也不需要 root。停止会话或关闭模块会自动移除隧道与推送的文件。

## 全屏投屏

点击工具栏的**全屏**按钮（或双击画面）即可把投屏铺满整个窗口：标题栏与导航栏让位，画面按比例居中显示在黑色背景上，设备控制保持可用。按 **Esc** 或点击右上角的**退出全屏（Esc）**按钮返回。

## 控制方式

- **鼠标**：点击即触摸，拖动即滑动，滚轮即滚动。坐标按镜像画布区域换算（留白区域不注入）。
- **导航键**：底部栏的 返回 / 主页 / 最近任务 按钮注入对应的 Android 按键。
- **文本**：在底部输入框输入文本，点击**发送到设备**，写入设备剪贴板并粘贴到焦点输入框。

## 会话状态

| 状态 | 含义 |
|---|---|
| 空闲 | 无会话；选择设备后开始。 |
| 连接中 | 推送/隧道/握手中；不可中断。 |
| 投屏中 | 镜像运行；画布显示实时画面。 |
| 已断开 | 设备或流中断；重新开始即可重连。 |
| 失败 | 启动失败；错误信息说明原因（如设备未授权）。 |

## 常见问题

- **设备列表为空**：先运行 `adb devices` 确认设备状态为 `device`（而非 `unauthorized`/`offline`），再点击刷新。
- **启动报 server 错误**：可能有其他 scrcpy 实例占用设备；停止后重试。
- **开始投屏后要等一两秒才出画面**：冷启动耗时主要在设备侧 scrcpy server（Android app_process + 硬件编码器初始化），平板上通常 1.5–2.5 秒。应用会在会话进入投屏状态后立刻请求一个关键帧，所以画面在设备开始出流后马上出现，无需等待固定的探测时间。
- **画面静止时不再重绘**：这是正常现象。设备编码器只在画面变化时发送帧，界面保留最后一帧；触摸、按键、滚动等操作会恢复出流。每次操作突发结束后应用会向设备请求一次关键帧，确保这次变化的最后一帧不会丢失。
- **滚动或输入时卡顿**：状态行会显示当前显示帧率（`… · 28 fps`）。想要最顺滑的滚动选**高清**（1600 px，最高 60 fps）；想要最清晰的文字选**原生**（设备分辨率，30 fps）。H.264 解码在宿主 CPU 上完成，开销随像素数增长，机器较弱时选**流畅**。若解码真的跟不上，会话会丢弃积压帧并在下一个关键帧处重新同步，而不是让延迟持续累积。
- **release 构建明显更顺**：每帧解码出的 BGRA 数据要复制并转换一次，未优化的 `cargo run` 构建喂不动原生分辨率的流（实测：同一会话 debug 构建显示 16 fps，release 构建 26–29 fps）。判断流畅度请用 `cargo run --release -p aps-app`。
- **诊断**：结束投屏时会在 stderr 打印管线计数——已显示帧数、首帧延迟、丢帧数、关键帧请求次数与重同步次数。
